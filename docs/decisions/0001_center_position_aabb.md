# Decision 0001: 衝突対象の位置を中心点としAABB比較に安全整数を許可する

- 状態: accepted
- 決定日: 2026-07-03
- 対象Phase: Phase 5 シミュレーター基盤

## 背景

Robot、Bullet、Obstacleは`Position`と`Size`で軸平行矩形を表すが、`Position`が矩形のどこを指すかは未定義だった。

Spawn Point、センサー距離、方位、Fireの目標位置を同じ基準へ揃えるには中心点が適している。一方、奇数サイズの矩形境界は0.5単位となるため、小数を保存せず比較するには2倍座標が必要になる。

現行の決定論規則は、乱数生成器を除くゲームロジックの各演算結果を符号付き32bit整数へ制限している。符号付き32bit座標同士のAABB比較で必要な2倍差分は符号付き32bit範囲を超えるが、JavaScriptの安全整数範囲には十分収まる。

## 決定

- Robot、Bullet、Obstacleの`position`は軸平行矩形の中心点とする
- AABB境界、包含、重複の比較に限り、座標を2倍した一時的な安全整数を許可する
- 一時値は`Number.isSafeInteger`で検証する
- 一時値をWorld State、保存データ、進捗、乱数状態、またはゲームロジックの数値結果として保持しない
- 比較結果はbooleanまたは検証結果だけとする
- 面積重複を衝突矩形の重複とし、辺または頂点だけの接触は重複としない

## 理由

- 位置、照準、距離、方位の意味を中心点へ統一できる
- 奇数サイズを丸めずに扱える
- Mapや座標へ不自然な半範囲制限を追加せずに済む
- 使用範囲を幾何比較だけに限定でき、保存データの32bit規則を維持できる

## 却下した選択肢

### Mapサイズと座標を制限する

2倍計算を32bitへ収められるが、コンテンツ制約が幾何実装都合へ依存するため採用しない。

### `position`を矩形の左下とする

AABB計算は単純になるが、Spawn Point、センサー距離、方位、照準位置がRobot中心と一致しないため採用しない。

### 中心点と左下を両方保存する

同じ状態を重複保持し、不整合の原因になるため採用しない。

## 影響

- Phase 5で共通AABB比較を追加する
- Map DefinitionのObstacleとSpawn Pointは中心点として検証する
- Phase 6以降の衝突、センサー、武器、爆発距離も中心点を基準とする
- Phase 5実装時に、共通データ規約、座標系、決定論規則の現在仕様へ限定例外を反映する
